> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stand up the AWS backend foundation — Cognito User Pool (email-only auth), AppSync GraphQL API, and DynamoDB single-table data model — deployed to an Amplify Gen 2 sandbox, with the mobile app wired up to configure Amplify and call `getCurrentUser()` end-to-end. Mobile client wraps the app tree in `AmplifyProvider` (configures Amplify on mount) and exposes a `useAuth()` hook returning a typed auth state.

```typescript
import { a, defineData, type ClientSchema } from '@aws-amplify/backend';

/**
 * Cadence data schema — Plan 2 baseline.
 *
 * Single-table design pattern adapted to Amplify's per-model tables:
 * every model is owner-authorized so users can only see their own data.
 * No public read, no admin read in v1.
 *
 * Models added incrementally across this plan:
 *  - Profile (Task 6)
 *  - Metric (Task 7)
 *  - ChatMessage (Task 8)
 *  - Subscription (Task 9)
 *
 * Plan 4 wires Dashboard / History queries; Plan 7 wires Coach mutations.
 */
const schema = a.schema({
  Profile: a
    .model({
      displayName: a.string(),
      dateOfBirth: a.date(),
      sex: a.enum(['male', 'female', 'other', 'unspecified']),
      diagnosisCodes: a.string().array(),
      consent: a.json(),
    })
    .authorization((allow) => [allow.owner()]),
});

export type Schema = ClientSchema<typeof schema>;

export const data = defineData({
  schema,
  authorizationModes: {
    defaultAuthorizationMode: 'userPool',
  },
});
```

- [ ] **Step 3: Create `amplifyConfig.ts`**

```typescript
/**
 * Loads amplify_outputs.json if present.
 *
 * In dev: sandbox writes amplify_outputs.json at the repo root after
 * `npm run sandbox` (Task 16). It's gitignored, so fresh clones and CI
 * builds will see null until they generate or download outputs.
 *
 * In production: the build pipeline (Plan 13) injects amplify_outputs.json
 * at compile time. AmplifyProvider treats a null config as "backend not
 * configured yet" and renders the app without auth — useful for offline
 * dev and snapshot tests.
 */
export interface AmplifyOutputs {
  version: string;
  auth?: {
    user_pool_id: string;
    aws_region: string;
    user_pool_client_id: string;
  };
  data?: {
    url: string;
    aws_region: string;
    api_key?: string;
    default_authorization_type: string;
  };
}

export function loadAmplifyConfig(): AmplifyOutputs | null {
  try {
    // The dynamic require ensures we don't break the bundler if the file is
    // missing. Metro will tree-shake this when the file exists.
    // eslint-disable-next-line @typescript-eslint/no-require-imports
    const outputs = require('../../../amplify_outputs.json') as AmplifyOutputs;
    return outputs;
  } catch {
```

```typescript
export function AmplifyProvider({ children }: PropsWithChildren) {

    }
  }, []);

}
```

```typescript
import { useEffect, useState } from 'react';
import { getCurrentUser } from 'aws-amplify/auth';

export type AuthState =
  | { status: 'loading' }
  | { status: 'signedOut' }
  | { status: 'signedIn'; userId: string; username: string };

/**
 * Read-only auth state.
 *
 * Plan 2 surface: tells the app whether someone is signed in right now.
 * Plan 8 builds sign-in / sign-up / sign-out flows on top of this.
 */
export function useAuth(): AuthState {
  const [state, setState] = useState<AuthState>({ status: 'loading' });

  useEffect(() => {
    let cancelled = false;

    getCurrentUser()
      .then((user) => {
        if (cancelled) return;
        setState({
          status: 'signedIn',
          userId: user.userId,
          username: user.username,
        });
      })
      .catch(() => {
        if (cancelled) return;
        setState({ status: 'signedOut' });
      });

    return () => {
      cancelled = true;
    };
  }, []);

  return state;
}
```

```markdown
# ADR 0002: Use AWS Amplify Gen 2 over Firebase or Supabase for the backend

- **Status:** Accepted
- **Date:** 2026-05-27
- **Deciders:** Solo founder

## Context

Cadence needs a backend that provides authentication, a typed data API,
file storage, and a managed LLM (Anthropic Claude) under one vendor with
one IAM model and one BAA story. The product is positioned for a B2C v1
freemium launch with a possible B2B2C v2 pivot — the architecture should
support both without rework.

Three candidates were evaluated:

1. **AWS Amplify Gen 2** — Cognito, AppSync, DynamoDB, Lambda, S3, Bedrock, KMS.
2. **Firebase + Vertex AI** — Firestore, Firebase Auth, Cloud Functions, Cloud Storage, Vertex AI (Gemini).
3. **Supabase + Anthropic API direct** — Postgres + RLS, Supabase Auth, Edge Functions, Storage, Anthropic API.

## Decision

Use **AWS Amplify Gen 2** with the full AWS service stack and Anthropic
Claude via **AWS Bedrock**.

## Consequences

**Easier:**
- Single AWS account holds every service the app needs — one bill, one IAM, one BAA when needed.
- Amplify Gen 2's typed schema produces an end-to-end TypeScript surface from the data model to the React Native client.
- Sandbox per developer enables fast inner-loop iteration without colliding with prod.
- HIPAA eligibility on every service used — future B2B2C pivot does not require rearchitecture.
- Bedrock keeps Claude data inside the AWS account perimeter, simplifying the audit story.

**Harder:**
- AWS surface area is larger than Firebase or Supabase; expect more "where does this live" lookup overhead at first.
- Amplify Gen 2 is younger than Firebase/Supabase; some patterns (advanced authorization rules, fine-grained Lambda authorizers) require digging into CDK escape hatches.
- Bedrock model availability per region lags Anthropic API direct by a few weeks. Acceptable.

**Trade-offs accepted:**
- We are slower to set up than Supabase (which could ship a v1 in ~4 weeks vs. our ~8) in exchange for the credibility and future-proofing of the AWS posture.
- We commit to AWS-flavored TypeScript conventions (CDK, Powertools, etc.) that don't transfer cleanly to other clouds — vendor lock-in is real.

## Alternatives Considered

- **Firebase + Vertex AI:** Rejected because the strongest argument was Gemini-as-default, but Cadence already picked Claude. Firebase Auth's OAuth ergonomics are nicer than Cognito's, but the rest of the stack does not justify dual-vendor complexity.
- **Supabase + Anthropic API direct:** Rejected because (a) faster shipping is not the top priority for a portfolio/learning project with no fixed deadline, (b) Cadence's eventual B2B2C pivot benefits from AWS's healthcare credibility, (c) handling Claude data via the Anthropic API requires a separate audit boundary that Bedrock removes.
- **Cloudflare Workers + R2 + D1 + Workers AI:** Considered for cost efficiency. Rejected because the HIPAA story is weak and the product's reputation needs a real cloud's posture from day one.
```
